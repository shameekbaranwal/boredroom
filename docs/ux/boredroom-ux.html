Design philosophy

Eight rules every screen has to pass

01Share onceThe talk stays in WhatsApp. So you share to Boredroom, it files everywhere, and one tap forwards the same text to the group. Never post twice.
02Each game keeps its own dayA game's "today" is whichever puzzle is current for it. Home is your agenda, sorted by what resets next, with a live clock on every open item.
03Scores are bait, details are earnedWho's in, scores and standings are public, so you want to play. Grids, routes and clues stay hidden until you file that puzzle. The parser decides what counts as a spoiler for each game.
04Rivalry, not guiltTenure, daily wins and memos. No XP, no leagues, no sad mascot. A reminder only before a game on your agenda resets, and only if you haven't filed it.
05The sheet is the jokeA very serious board keeps its records in a spreadsheet: rows, cells, a formula bar. The formula bar is real, and every screen is a query you can edit.
06Built for a big boardFifteen people, a different subset every day. Every list, chart and agenda line has to read at that size, not just with three friends.
07Unknown never means rejectedA result we can't read still counts as "played". Scoring catches up when the game gets a parser.
08Deadpan memo, plain buttonsHeadings, chips, memos and notifications speak boardroom. Buttons never do: "join", "file", "add a game".

Platform

One web app for v1

An installed web app (PWA) on Android appears in the share sheet through the Web Share Target API, and gets push notifications. iPhone home-screen web apps get push too (iOS 16.4+). One web codebase covers Android, iPhone and desktop with no store fees. A native Android app comes after v1.

AndroidInstall from Chrome. Boredroom appears in the share sheet.
iPhoneHome-screen web app. Paste-based, or a free Shortcut later.
DesktopPlain website. Clipboard suggestion when you come back to the tab.
Themes

Build it so the look can change

Spreadsheet is the launch look, but people will pick from the other directions later. So the UI is written once against tokens, on web and Android alike.

Semantic tokens onlyScreens use surface, ink, accent, ok, todo, note, g1–g7, member hues, and heading, body and number fonts. Never a raw color.
Layout is a token toolayout: sheet gives rows, gutter numbers, a formula bar and sheet tabs. layout: free gives cards and pills. Components take the variant; screens never branch on a theme.
One query, many skinsThe formula bar is one query model. Spreadsheet shows =review(…), Night Ledger select …, free layouts plain chips.
Themes are dataEach theme is a JSON file: tokens, layout, finish, plus a light and dark pair. It becomes CSS variables on web and a Compose theme on Android.

The WhatsApp bot

The forward button and the whatsapp exports cover the daily need. A bot in the group itself ("strands just reset", reading results people paste) stays parked: bridges are unreliable and risk the account. It would sit on the same API, so nothing in v1 blocks it.
